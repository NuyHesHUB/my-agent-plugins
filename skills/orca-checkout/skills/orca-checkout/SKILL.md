# Orca Checkout

Orca 워크스페이스는 프로젝트를 git worktree로 복사해 그 안에서 작업하는 구조다. 이 스킬은
"워크스페이스에서 검증 끝난 작업을 로컬 프로젝트 브랜치로 반영하고, 사용자 확인 후
워크스페이스를 치운다"는 반복 작업을 처리한다.

**승인 범위**: `/orca-checkout`을 호출하는 것 자체가 커밋과 브랜치 이동(1~3단계)에 대한
승인으로 간주한다. 매 단계마다 "커밋해도 될까요?"처럼 되묻지 않는다. 단, **워크스페이스
삭제(4단계)는 호출만으로 승인된 것이 아니다** — 체크아웃 결과를 보고한 뒤 반드시 사용자에게
프롬프트로 삭제 여부를 물어보고, 승인 응답을 받은 뒤에만 삭제한다. 또한 아래 "중단 조건"에
해당하면 자동 진행을 멈추고 사용자에게 확인을 받는다.

## 0. 선행 확인

- `git worktree list`로 전체 워크트리를 조회한다.
- 현재 디렉터리(cwd)가 경로에 `/orca/workspaces/`를 포함하는 항목인지 확인한다. 포함하지
  않으면("이미 로컬 프로젝트 경로에서 실행함") 아무것도 하지 않고 사용자에게 알린다.
- `git worktree list`의 나머지 항목 중 `/orca/workspaces/`를 포함하지 않는 항목을
  "로컬 프로젝트 경로"로 지정한다. 그런 항목이 0개거나 2개 이상이면 자동 선택하지 말고
  사용자에게 어느 경로인지 물어본다. (**중단 조건**)

## 1. 현재 워크스페이스 커밋

- `git status --short`로 미커밋 변경을 확인한다.
- 변경이 있으면 저장소 최근 커밋 스타일(`git log --oneline -5`)을 참고해 커밋 메시지를
  작성하고 커밋한다. 세션에 적용 중인 attribution 규칙(있다면)을 커밋 메시지 끝에 포함한다.
- 변경이 없으면(이미 전부 커밋됨) 이 단계는 건너뛴다.
- 완료 후 커밋 메시지와 변경 파일 목록을 보고에 포함한다.

## 2. 로컬 프로젝트 경로 상태 점검

- 로컬 프로젝트 경로에서 `git status --short`로 미커밋 변경을 확인한다.
- 비어 있으면 3단계로 진행한다.
- 변경이 있으면:
  - 그 변경이 지금 옮기려는 브랜치와 무관한 별개 작업이라면, 고유 태그를 붙여
    `git stash push -u -m "orca-checkout-<timestamp>"`로 보관한다(바로 `git stash`나
    `git stash pop`을 쓰지 않는다 — 스택이 다른 세션과 공유된다). 보관 직후
    `git stash list --format='%H %gs'`로 SHA를 기록해 보고에 남긴다.
  - 변경 내용이 애매하거나 되돌리기 꺼려질 정도로 크면, stash하지 말고 사용자에게 먼저
    알리고 진행 여부를 확인한다. (**중단 조건**)

## 3. 브랜치 이동 (워크스페이스는 아직 지우지 않는다)

- 로컬 프로젝트 경로가 보던 브랜치를 기억해둔다(나중 보고용).
- 현재 워크스페이스에서 `git checkout --detach`를 실행한다. 워크스페이스 폴더와 파일은
  그대로 남고, 브랜치 점유만 풀려서 로컬 프로젝트가 같은 브랜치를 체크아웃할 수 있게 된다.
  (`git worktree remove`를 여기서 쓰지 않는다 — 삭제는 사용자 확인을 받은 뒤 4단계에서 한다.)
- 로컬 프로젝트 경로에서 `git checkout <워크스페이스 브랜치명>`을 실행한다. 점유가 풀렸으므로
  성공해야 한다.
- 체크아웃 결과를 사용자에게 보고한다: 로컬 프로젝트 경로, 체크아웃된 브랜치명, 커밋 메시지,
  stash를 만들었다면 그 SHA와 복원 방법(`git stash apply <sha>`).

## 4. 사용자 확인 후 워크스페이스 삭제

- 3단계 보고와 함께 "로컬 프로젝트에서 결과를 확인한 뒤, 이 Orca 워크스페이스를 삭제할지
  알려달라"고 **프롬프트로 질문하고 사용자의 응답을 기다린다.** 묻지 않고 삭제하지 않는다.
- 사용자가 삭제를 승인하면, **아래 명령을 전부 로컬 프로젝트 경로에서(cd <로컬 경로> 후)
  실행한다.** 워크스페이스 안(cwd)에서 자기 경로를 지우면 셸의 cwd가 사라져 이후 명령이
  전부 실패한다(이전 버전의 결함).
  1. `git worktree remove <워크스페이스 경로>`
     - untracked 파일이 남아 있어 거부되면 내용을 먼저 확인하고, 버려도 되는 파일만 있을 때
       `--force`를 쓴다. 중요해 보이는 파일이 있으면 중단하고 사용자에게 알린다. (**중단 조건**)
  2. `orca-ide worktree rm --worktree path:<워크스페이스 경로> --force --json`으로 Orca 쪽
     메타데이터(카드/워크스페이스 목록)를 정리한다. 브랜치가 이미 로컬 프로젝트에
     체크아웃되어 있어 git이 브랜치 삭제를 막아주므로 안전하다.
- 사용자가 삭제를 거부하면 워크스페이스를 그대로 두고, 현재 워크스페이스가 detached HEAD
  상태임을 안내한다(이어서 작업하려면 새 브랜치를 만들거나, 로컬 체크아웃을 되돌린 뒤
  브랜치를 다시 체크아웃해야 한다).

## 5. 마무리 보고 (중요)

4단계의 삭제는 **지금 실행 중인 세션 자신의 cwd(오르카 워크스페이스 폴더)를 지운다.**
따라서:

- 삭제를 실행한 뒤로는 이 세션에서 추가 쉘 명령을 실행하지 않는다(cwd가 사라져 실패할 수 있다).
- 최종 보고에 다음을 명시한다: 로컬 프로젝트 경로와 체크아웃된 브랜치명, stash를 만들었다면
  그 SHA와 복원 방법, 그리고 삭제했다면 "이 오르카 워크스페이스는 삭제되었으니 이 세션은
  종료하거나 다른 워크스페이스로 전환해 달라"는 안내.
